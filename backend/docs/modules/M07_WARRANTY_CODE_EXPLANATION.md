# M07 warranty code explanation

M07 is a stacked dependency on the current M06 feature branch while PR #6 remains open. Read the API contract for all51 endpoints and the technical document for ER/lifecycle/date/security boundaries.

| File | Actual responsibilities |
|---|---|
| prisma/schema.prisma | Eleven M07 models/eight enums. Immutable versioned terms, exact commissioned/item coverage, private evidence, claim assessments/provider responses/decisions, canonical ownership and idempotency/access records. No duplicate inventory/installation/customer identity. |
| prisma/migrations/20261031000700_m07_warranty_management/migration.sql | Offline additive DDL plus canonical coverage uniqueness, exact installed identity/quantity, policy publication/backdating, frozen terms/dates, lifecycle/reviewer/provider/date/proof guards and immutable audit/evidence. NOT APPLIED. |
| warranties/validation.ts | Strict policy/date/registration/claim/review/evidence schemas; explicit configured durations and start rules; bounded UUID arrays/text/pagination; date-only observed facts and version/idempotency keys. |
| warranties/common.ts | caseWorker/admin and jobScope establish explicit Support grants or summary-only Sales/assigned Technician access. post authorizes before replay, hashes canonical request and stores frozen result. registration/claim helpers scope/lock/version-check; saveRegistration/saveClaim enforce transition graphs and append unified owned history. |
| warranties/dates.ts | UTC civil dates, start-inclusive/end-exclusive effective status, day addition and month/year clamping. Expiry is server-calculated, not client-authoritative or an editable EXPIRED status. |
| warranties/policy.service.ts | Explicit ADMIN policy creation/publication/rename/deactivation; immutable coverage/provider kind, bounded terms and retrospective-effect reason. Grant/revoke scoped Support installation access without modifying User roles or M05 assignments. |
| warranties/eligibility.ts | installedIdentity uses the shared M05 commissioning guard and exact installed line/serial. activation calculates candidate source/expiry and explains missing proof, effective range, current policy and registration deadline. Never maps warehouse dispatch/site receipt to customer delivery. |
| warranties/registration.service.ts | Creates exact frozen coverage; edits evidence dates only pre-review; submit retains pending evidence on findings; independent ADMIN persists activation/rejection snapshot; void preserves historical dates/claims. |
| warranties/assessment.ts | Advisory claim evaluation of original dates/identity/documents/exclusions/conditions/provider/prior cases. Human attestations are stored, never interpreted as automatic legal certainty. Facts fingerprint detects later changes. Database failures propagate rather than pretending they are evidence findings. |
| warranties/claim.service.ts | Investigation/assignment/state commands, immutable assessment, human decisions, recorded provider communications/responses, resolution/closure. Independent ADMIN final approval and latest external provider acceptance are distinct from internal eligibility. No later-module side effect. |
| warranties/read.service.ts | Scoped paginated policies/registrations/cases/history/decisions/evidence, date-derived coverage, expiry/pending/summary, selected-policy unregistered identities, redacted M08 context and narrow Finance approved outcomes. Private original installationSnapshot is omitted from normal registration reads. |
| warranties/evidence.service.ts | Auth/version preflight before bytes, secure existing adapter, name/MIME/signature/checksum, exact owner metadata, file cleanup on known rollback and protected integrity-checked download. |
| warranties/routes.ts | /api/warranties JSON/binary endpoints, explicit roles, route validation/order, existing session/Origin/CSRF, body limits and upload rate limits. |
| installations/review.service.ts | Extracts commissionedRecord(tx,row) read-only handoff after caller scope. Original commissioned endpoint authorization/payload stay unchanged; M07 proves its own access before calling. |
| src/app.ts, config/env.ts, .env.example | Mount warranty router, narrowly extend private binary evidence exception, and configure separate safe storage/size without secrets or dependency changes. |

A JSON write authorizes current scope before looking up its idempotency key, locks registration before claim, checks version, validates current facts, writes one domain action plus history/decision and finalizes a frozen operation result in one Serializable transaction. A stale version/duplicate coverage/constraint/race rolls back. File storage happens outside the transaction with creation-receipt cleanup and uncertain-commit reconciliation; no raw private path is exposed.

Policy version stays frozen on each registration; active dates/approval cannot be edited after activation. Claims carry a separate contentRevision: factual/evidence/provider changes stale assessments; state/assignment changes alone do not manufacture new facts. Current facts fingerprint is checked before decision. Original submitter cannot approve/deny their own case. A provider response only records evidence and never directly becomes a final decision.

Static compilation cannot execute SQL triggers, calendar parity/races/private storage/CSRF or real integration. See M07_VERIFICATION.md for exact files, checks and runtime limitations. No runtime tests, migrations, server, sample records, frontend or M08+ code are included.
