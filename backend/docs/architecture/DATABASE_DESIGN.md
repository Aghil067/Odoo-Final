# Backend database design index — M01 + M02 + M03

Canonical model: `backend/prisma/schema.prisma`. Canonical deployment history: `backend/prisma/migrations`. Use PostgreSQL; Prisma Client/CLI remain pinned together at 6.19.3. Existing migrations are preserved and must run in order after operator review; neither was applied by this work.

M01 owns User/Session, Customer, Site, Lead, LeadActivity and LeadStatusHistory. [M01 technical documentation](../modules/M01_CRM_TECHNICAL_DOCUMENTATION.md) describes these fields, contact normalization, decimal amounts, ownership and SERIALIZABLE transactions.

M02 adds SiteSurvey, RoofAssessment, ElectricalAssessment, SurveyAttachment, SurveyStatusHistory and SurveyReview. [M02 technical documentation](../modules/M02_SITE_SURVEY_TECHNICAL_DOCUMENTATION.md) contains the ER diagram, field rules and approval lifecycle. Each survey references existing customer/site/lead/user records; the composite Lead FK fixes lead/site/customer identity. There is no second User table or new Role value.

`20261031000200_m02_site_survey` adds one existing-Lead composite unique index and new M02 tables/enums/indexes only. Additional SQL enables btree_gist and supplies one-active-per-lead, one-running-visit, appointment-range exclusion, draft/terminal guards and append-only review/history/evidence metadata. M01's pg_trgm setup and additional CHECK constraints remain untouched. All new CRM/survey deletion relations are restrictive.

Every mutation carries optimistic version and commits audit/history atomically through existing serializable transactions. Approval snapshots preserve the reviewed content and selected master-data versions; reassessment uses a new linked row. File bytes live in a private adapter, not PostgreSQL; metadata includes a digest but excludes public storage URLs.

SQL triggers/exclusion constraints cannot be fully represented or validated by Prisma 6's schema DSL. Retain the custom SQL in later migration reviews; do not regenerate/replace migration history, run db push to discard it, reset a database or treat static validation as proof of execution. M03 has no tables here and must later reference an eligible approved survey/version/review through its guarded handoff.

M03 update: [solar configuration/BOM documentation](../modules/M03_SOLAR_CONFIGURATION_TECHNICAL_DOCUMENTATION.md) defines nine additional catalog/template/configuration/BOM/history/review models, Decimal arithmetic, immutable snapshots and the ER diagram. It adds unique composite survey/review keys to preserve exact M02 identity/approval references without changing business rows. Migration `20261031000300_m03_solar_configuration` depends on M02 PR #2/migration; neither is bypassed. Earlier future-tense M03 notes above describe the original M02 boundary, now implemented separately. M04 stock management still has no backend tables here.

M04 adds eleven inventory/warehouse models and three enums through 20261031000400_m04_inventory_warehouse. SolarComponent is the sole catalog. Decimal balances separate usable/reserved/quarantined stock; ledger insertion triggers apply stock deltas, deferred checks reconcile active reservations and serial counts, and immutable operations/events retain audit trace. See [M04 ER/lifecycle/concurrency documentation](../modules/M04_INVENTORY_TECHNICAL_DOCUMENTATION.md). Migration is NOT APPLIED; previous statements about absent M04 tables describe the historical M03 boundary.

M05 adds twelve installation models and eight enums in 20261031000500_m05_installation_management. It reuses existing configuration/BOM/reservation/dispatch/customer/site/lead/component/serial masters. Composite job ownership FKs, exact dispatch identity, Decimal limits, unique installation serial claims, version/executionRevision, immutable review/history/evidence and frozen terminal children support the workflow. New protective guards reject inventory returns that orphan installed equipment; existing M01–M04 migrations/history are untouched. See [M05 ER/state/concurrency design](../modules/M05_INSTALLATION_TECHNICAL_DOCUMENTATION.md). Migration NOT APPLIED.

M06 adds eleven workforce models and four enums in 20261031000600_m06_technician_management. User remains the identity; SiteSurvey and InstallationAssignment/InstallationJob remain the sole authoritative work assignments. Shared User-row locking and SQL cross-table interval/leave/rest checks complement transaction-aware application calendar/qualification checks. GiST exclusions protect effective schedules, weekly shifts, historical team membership and active leave/blocks. Existing M01–M05 migrations unchanged; M02 btree_gist prerequisite reused. See [M06 ER/availability design](../modules/M06_TECHNICIAN_TECHNICAL_DOCUMENTATION.md). Migration NOT APPLIED.

M07 adds eleven warranty models/eight enums in20261031000700_m07_warranty_management. Existing SolarComponent/InventorySerialUnit/InstallationJob/Equipment/CommissioningReview identities are reused; composite evidence/history/decision ownership, canonical unique policy/item coverage, Decimal quantities, immutable policy/approval snapshots, explicit civil-date expiry and append-only audit are protected by application transactions plus additive SQL guards. Expiry is derived, not a mutable status. No existing source records/migration files are rewritten; M06 remains a stacked dependency. See [M07 ER/start/claim/concurrency design](../modules/M07_WARRANTY_TECHNICAL_DOCUMENTATION.md). Migration NOT APPLIED; PL/pgSQL execution and concurrency remain runtime-unverified.

M08 adds16 service models/seven enums and SERVICE WorkforcePurpose in20261031000800_m08_service_management. Composite source/assignment/visit ownership, one current ticket assignment, active visit GiST exclusion/one-running uniqueness, versioned history and logical check/feedback ordering, immutable diagnosis/evidence/closure/SLA records, pending-only parts and unique maintenance occurrence identities support execution. Shared User locks and additive M02/M05/M06 hooks include service in cross-source conflicts/unavailability/deactivation while preserving original masters and prior migration bytes. See [M08 ER/workflow/SLA/concurrency design](../modules/M08_SERVICE_TECHNICAL_DOCUMENTATION.md). Migration NOT APPLIED; custom SQL and runtime concurrency remain unverified. No stock balance, warranty decision or finance record is created by service execution.
